Decision card · protocol v1

A forty-one point difference between two copies of the same software.

Nothing was changed between them. Same recipe, same training data, same settings — only the random seed differs. The standard test reports the gap as overwhelming. There is nothing there to find.

Naive episode-level read

How big does a gap have to be before it means something?

Call it a difference atFires onFalse-positive rate

This is not a cherry-picked pair.

Every one of those rejections is a mistake, and we know it is a mistake without having to argue about it, because both arms came from the same recipe.

What a card can say.

Supported improvement

The change helped.

The gap is larger than the noise of running the same thing twice, measured on this deployment rather than assumed.

Supported regression

The change hurt.

Same bar, in the other direction. This is the state that should stop a rollout, and the only state that should.

No material difference

Nothing detectable changed.

The card on this page. A gap this size is what the same software produces against itself.

Insufficient evidence

Not enough data to say.

Reported with the number of runs that would settle it, so the answer is a plan instead of a shrug.

What this page does and does not show.

Read this before you quote it

The arms are not two builds. They are two groups of retrainings of one recipe, labelled A and B so the card has something to compare. Presenting them as a vendor release would be the invented story this page exists to replace.

Every figure here is a rejection rate. This page reports how often a decision rule fires when there is nothing to find. It does not report how noisy retraining is on this panel, which is a separate measurement belonging to a paper still under review, and which is deliberately not published here.

Now ask what your vendor's number would look like under this test.

If a release was measured once, this is the question it has not answered.

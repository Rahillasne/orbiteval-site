How to read the calls
A skill counts as regressed only when the drop clears both an absolute floor and the noise at that skill's episode count. The rule is stated rather than hidden, and it is the same rule the command line tool uses.

  

    
Regressed
The whole 95% interval of the change sits at or below −5 points. Real, and large enough to matter. Exit code 1 in the CLI.

    
Suspect
The skill fell at least 5 points but the interval still reaches above the floor. At this episode count the drop is not distinguishable from noise. Run more episodes on this skill before deciding.

    
Held
No drop beyond the floor. Not "unchanged": the resolution line says how large a drop could hide here.

    
Improved
The whole interval is above zero. Reported, never used to excuse a regression elsewhere.

    
Underpowered
Fewer than ten episodes on this skill. No call can be made at all, so none is.

    
No multiplicity correction
Ten skills tested at once will produce some false flags even when nothing changed. The readout states the expected number instead of silently correcting for it, because on this objective the correction removed the flags that were doing the work.

Questions people ask first

  

    
Does my data leave my computer?
No. This page loads a Python runtime into your browser (Pyodide) and runs the same open-source package you would install with pip. There is no server behind this page; it is static files. The chat is different: files you send there go to the assistant's server for the reply and are not stored.

    
Why 5 points and 2 standard errors?
On a banked battery of identical-recipe retrains, an unpriced rule (any drop with p ≤ 0.05) fired on 81% of releases where nothing had changed; the priced rule fired on 2.5%. A rule that always rings is a rule people switch off. Both thresholds are printed in every readout and can be changed in the CLI.

    
My two versions were not evaluated on the same episodes.
Then the comparison is unpaired and the intervals are wider; the readout says which it used. If you can, evaluate both versions with the same evaluation seed and the same initial states. The interval roughly halves.

    
What does "smallest drop this file can call real" mean?
With 100 episodes per skill, a real drop of 8 points usually cannot be separated from noise; with 10 episodes, a drop of 30 points often cannot. The readout computes that number for your file so you know what "held" is worth. More episodes on the skills you care about is the fix, and the CLI's power command sizes it.

    
Where does the method come from?
From a corpus of 701 controlled retrainings of robot policies across four policy classes, every wave pre-registered before scoring, and from the public benchmarks re-cut on the Capability Arena. The statistics are ordinary: Wilson and Newcombe intervals, paired comparison when episodes align, a stated floor. What is unusual is refusing to print a number the data cannot support.
